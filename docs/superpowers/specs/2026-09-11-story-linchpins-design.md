# Story Linchpins — design

A linchpin is an irreversible player choice that moves faction standing and
closes off endings. Mayor Tina is the first; the system exists because there
will be more.

## Why a system rather than a one-off

Tina alone could be hardcoded. The requirement is explicitly that more of these
follow, and the failure mode of hardcoding the first one is that the second
copies it, the third copies the second, and ending-gating logic ends up smeared
across the codebase with no single place to ask "what has the player closed
off?".

## What already exists — and must not be duplicated

`src/act2.js` already carries the entire consequence vector:

| State | Shape | Mutator |
| --- | --- | --- |
| `humanity` | 0–100, tiers `human → strained → symptomatic → outed` | `adjustHumanity(delta)` |
| camp `bond` | 0–`ACT2_MAX_BOND` per camp | `adjustCampBond(id, delta)` |
| camp `status` | `alive/robbed/culled/recruited/turned` | `setCampStatus(id, status)` |
| `queenStatus`, `eggsStatus` | enums | setters |
| endings | 10 ids, chosen by `pickAct2Ending(state)` | — |

Linchpins therefore add **no new consequence state**. They record a decision and
apply deltas to the above. The only change to ending logic is a lock filter.

## Data shape

`src/storyLinchpins.js` — a frozen registry:

```js
mayor_tina: {
    id: 'mayor_tina',
    resolutions: {
        killed: {
            humanity: +5,
            campBondAll: +1,
            locksEndings: ['alien_exodus', 'full_brood', 'mothership_infection'],
            codexNote: 'linchpin_tina_killed'
        },
        joined: {
            humanity: -30,
            campBondAll: -2,
            locksEndings: ['clean_escape', 'scorched_sky'],
            codexNote: 'linchpin_tina_joined'
        }
    }
}
```

Adding a linchpin is a data entry plus a trigger. No new plumbing.

## State and persistence

Stored in the existing `hb_act2_v1` record:

```js
linchpins: { mayor_tina: 'killed' }
```

`normalizeAct2State` defaults it to `{}` and drops unknown ids and unknown
resolutions, so a save written by a later build cannot put an older build into a
state its cascade does not understand. Internal `version` bumps; the storage key
does not change, so export/import and `clearSaveData()` keep working untouched.

**Resolutions are write-once.** `resolveLinchpin` is a no-op if that linchpin is
already recorded — the point of a linchpin is that it cannot be re-rolled, and
without the guard a repeated trigger would apply its humanity delta twice.

## Ending locks

`pickAct2Ending` gains one guard: an ending whose id appears in the accumulated
lock set is skipped as the cascade evaluates. The cascade's order and conditions
are otherwise unchanged.

**A guaranteed floor is mandatory.** Enough locks could otherwise leave zero
reachable endings — a soft-lock generated by the system meant to add
consequence. `MIXED_CREW` is already the cascade's catch-all and is never
lockable; a test asserts that every subset of locks still yields an ending.

## Mayor Tina

Her encounter state machine (`mayorTinaEncounter`) stays the authority on the
secret sequence. The linchpin only observes the outcome.

| Step | Behaviour |
| --- | --- |
| First hit | Lands. Warning line. She turns hostile. |
| Hits 2–4 | Normal damage. |
| Death | Resolves `mayor_tina: killed`. |
| Hive path | Resolves `mayor_tina: joined`. Trigger stubbed; the quest that fires it is future work. |

Four hits total, per the brief: "shoot Tina, they start to attack after a
warning, then you kill them after 3 more hits."

If she is damaged mid-encounter the sequence aborts cleanly rather than being
left half-played.

## Narrative reasoning behind the lock tables

The first draft of this spec guessed at these. They were then checked against
what each ending actually *means* in `src/endingExplanations.js` and what its
cascade branch actually *requires*, and two guesses changed.

Tina's encounter state carries `originalOverlay` and `transformedOverlay`: she
transforms. Killing her is therefore not murdering a civic leader, it is
exterminating an infiltrator wearing one's face — which is why camps approve,
and the reason the pro-camp direction is coherent at all.

**`killed` locks the three alien-aligned endings:**

| Ending | Means | Why killing Tina closes it |
| --- | --- | --- |
| `ALIEN_EXODUS` | "rejected the Queen but brought the allied beings off-world" | Requires every hive site allied. You killed the Queen's agent; the hives do not ally with you. |
| `FULL_BROOD` | all camps culled, obedience maxed | Requires `queenObedience >= MAX`. Killing her agent breaks the obedience path. |
| `MOTHERSHIP_INFECTION` | "smuggled the infection aboard disguised as a clean rescue" | You destroyed the infiltration you would have been carrying. |

**`joined` locks two:**

| Ending | Means | Why joining closes it |
| --- | --- | --- |
| `CLEAN_ESCAPE` | "broke the hive link, purged the eggs, escaped with all human survivors" | Definitionally impossible: you *are* the hive link. |
| `SCORCHED_SKY` | "incinerated every survivor camp and purged the eggs" | A carrier does not purge its own brood. |

**Deliberately not locked by `joined`:** `OUTED_ESCAPE` — "the survivors boarded
knowing what you are". Becoming a bug makes that ending *more* apt, not less.
Locking it would have been the tidy-looking wrong answer. `EMPTY_HUSK` likewise
stays open: fleeing alone remains available to anyone.

**Humanity deltas, revised.** The first draft gave `killed` a `+10`. `humanity`
is described in the hive-swarm design as "visible human control and masking" —
it tracks the player's own infection, not their reputation. Killing an
infiltrator does not cure the player. It is reduced to `+5`, as reinforced cover
from acting decisively human in public, and camp standing carries the real
reward. `joined` drops it `-30`: that is a transformation step, not a favour.

## Deliberately out of scope

- **The alien hive quest itself.** The `joined` resolution and its trigger point
  exist; the quest that reaches them does not.
- **Surfacing locks to the player.** A choice that silently removes endings
  reads as a bug. The codex note ids are reserved here, but the UI that reads
  them is a follow-up — shipping the mechanic before the feedback is acceptable
  only because nothing is player-visible yet either way.

## Testing

1. Resolutions apply their humanity and bond deltas exactly once.
2. A second resolution attempt on the same linchpin is a no-op.
3. Locked endings are skipped by the cascade.
4. **Every subset of possible locks still yields an ending.**
5. Old saves without `linchpins` normalize to `{}`; unknown ids and resolutions
   are dropped.
6. Tina dies on the fourth hit, not the first.
