## P0: freezes

- [ ] **S53-01. Shader compilation freezes the game for 30-40 s on Windows.**
  - **Evidence:** the PC froze for 32 s after deploy, 36 s on the first frame after the Mothership dialogue, and 38 s on the retry. Each lines up with a jump in compiled shader programs. Peak programs rose from 206 at v2.4.16 to 468, and the worst freeze from 3.2 s to 38.4 s, across Sprint 52 uploads. The Deck shows the same moments at 5-9 s.
  - **Measure first:**
    - list `renderer.info.programs` by cache key on `v2.4.16-beta` and on the head, in the same start view;
    - count programs per source: new world-story and expansion models, shadow-depth variants, materials patched with `onBeforeCompile`, and props with practical lights.
  - **Then:**
    - share one program cache key across patched materials;
    - keep a fixed light budget, so streaming props never change the scene's light count and recompile every lit material;
    - make the startup warm-up compile what the first view really draws, with `compileAsync` and `KHR_parallel_shader_compile`, before control is handed over.
  - **Accept:**
    - on the Windows machine, no main-thread task over 250 ms from deploy through the first 5 minutes, first life and retry;
    - shader programs at or below the release count, or explained;
    - the Deck re-measured on the same route.
- [ ] **S53-02. The scene is too heavy to hold frame rate.** At the end of the PC run: 7.6 M triangles, 890 draw calls, a 3.6 GB JS heap peak, and about 15 fps on both machines. Measure triangles and draw calls per prop source and set a room budget. Owner art stays: never crush props ([lived-in pass 2](lived-in-world-pass-2-2026-10-09.md)); use LODs, instancing and culling instead. Targets: the [remediation plan](playtest-remediation-steam-deck-and-pc-2026-10-12.md) p95s (Deck ≤ 33 ms, PC ≤ 16.7 ms).

## P1: the right operator, the right input

- [ ] **S53-03. Switching class can leave the previous class on screen.**
  - **Owner:** on the Deck the hero select still showed the Scout after switching to the Tank.
  - **Route (from the capture):** pick the Scout, ENTER ARMORY, RETURN TO MAIN MENU, pick the Tank, ENTER ARMORY. The deployed class was correct, so this is presentation only.
  - **Suspects:** the hero preview's stale-request guard (`pendingPreviewType`, `heroPreviewRequestGeneration`), which can drop the Tank request after the door transition; and the preview being rebuilt lazily on menu entry since `56f74c81`.
  - **Accept:** a GPU probe that runs this route, plus every pair of class switches, and checks the model on the hero select and in the Armory.
- [ ] **S53-04. Deck controls are logged as keyboard.**
  - **Owner:** only the Deck's controls were used.
  - **Log:** the input mode flipped controller/keyboard 13 times, and both deploys recorded `deploy-input-provenance: keyboard`.
  - **To find:** which Steam Input action-set path emits key or mouse events (trackpads, back buttons, the menu set). Fix the classification so the deploy record reflects the real device and the prompts show the right glyphs.
  - This unblocks #53 evidence from logs (see the [controller navigation map](../design/controller-navigation-map.md)).
- [ ] **S53-05. New players can squad-wipe on O2 before learning the bubble.** In the session the Scout walked into the cryo chunks and drained from 100% to 0% in 5 minutes, after choosing "run me through protocols". This is a design check, not a bug: have the tutorial teach O2 before the player can leave the bubble's range, or warn at 50%.

## P1: PC UI ([audit](pc-ui-defects-and-feedback-audit-2026-10-15.md))

- [ ] **S53-06 (DEF-01).** Settings → Camera & HUD: "THIRD-PERSON — SHOULDER" spills into CAMERA DISTANCE. Give the controls `min-width: 0` and an ellipsis, and let the panel grow on PC.
- [ ] **S53-07 (DEF-02).** The main menu rotates through the `safe_ship` playlist. Give the menu its own non-rotating context (the main theme).
- [ ] **S53-08 (DEF-03).** The Mothership uplink panel is capped at 1150 px, so a PC screen is mostly black, and the channel badge clips. Scale it up on wide screens and let the header wrap.
- [ ] **S53-09 (DEF-04).** The Operator Select gameplay preview is a 75 px 16:9 sliver. Make it square and larger, and fill the left column evenly.
- [ ] **S53-10 (DEF-05).** The Operator Select back button clamps to 9.5 px in a muted colour. Make it at least 12 px with real contrast, and check the Armory's own back button too.
- [ ] **S53-11 (DEF-06).** Set a global font floor: 11 px for text, 12 px for buttons. Audit every `clamp()` below it; add it to the HUD/menu layout tests.

**Accept for S53-06 to S53-11:** screenshots at 1920×1080, 2560×1440 and 1280×800 (Deck), plus the audit's §5 checklist.
