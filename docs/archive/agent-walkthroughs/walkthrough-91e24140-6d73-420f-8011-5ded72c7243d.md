## 🛠️ Changes Implemented

### 1. Visual & Asset Load Optimizations (LCP & transfer size)
- **Hiding Splash Screen Initially**:
  Added the `hidden` class to `<div id="splash">` inside [index.html](file:///home/caveman/Desktop/icecave/hunker-bunker/index.html). This prevents the browser from loading splash background assets or painting the splash screen underneath the loading overlay during page load.
- **WebP Background Images**:
  Updated the background CSS rules in [style.css](file:///home/caveman/Desktop/icecave/hunker-bunker/style.css) to use highly optimized WebP versions instead of PNGs:
    - `/bg.png` (757KB) $\rightarrow$ `/bg.webp` (66KB)
    - `/menu_bg.png` (568KB) $\rightarrow$ `/menu_bg.webp` (24KB)
    - `/door.png` (1.0MB) $\rightarrow$ `/door.webp` (161KB)
- **Preload WebP Assets**:
  Modified the preloader in [main.js](file:///home/caveman/Desktop/icecave/hunker-bunker/main.js) to preload `/door.webp` and `/menu_bg.webp` instead of PNG files, reducing the critical preloading payload weight by **1.38MB**.

### 2. Startup Execution Optimizations (TBT & CPU)
- **Deferred dynamic ThreeGame loading**:
  Postponed the dynamic import of `threeGame.js` (741KB minified chunk) and creation of the WebGL `ThreeGame` instance from `DOMContentLoaded` page load to the document body click event.
- **Lazy-Loaded Gameplay Assets Manifest**:
  Split the main preloading list in [main.js](file:///home/caveman/Desktop/icecave/hunker-bunker/main.js) to extract **38 gameplay-only textures** and **11 audio tracks** (which total over **30MB** of weight and significant CPU parsing overhead). These are now lazyloaded inside the click handler via `gameplayManifest`.
- **Silky Smooth Click Transition & Boot/Error State**:
  Modified the click handler in [main.js](file:///home/caveman/Desktop/icecave/hunker-bunker/main.js) to:
    1. Show a loading state: `> BOOTING TACTICAL WEBGL CORE... (XX%)` with progressive asset loading feedback.
    2. Await the idempotent `initializeGame` promise.
    3. Remove `.hidden` from the splash screen and transition only once WebGL init successfully completes.
    4. Provide retry options if initialization fails.
