# ❄️ Hunker Bunker v2.2.0-Beta — Sprint 26 Release Notes

Sprint 26 turns the multiplayer runtime built in Sprint 21 into something
Steam-native and production-safe. Production Steam authentication is
confirmed live, real Steam Lobby integration (Friends invite, Join Game,
Rich Presence) is code-complete, and several silent multiplayer/Steam-sync
gaps were found and closed along the way.

## 🚀 Key Highlights

### 🔑 Production Steam Auth, Confirmed Live

- **Real end-to-end verification:** the trusted Steam backend at
  `steam.tuesdaycinema.club` (self-hosted Docker + Caddy, behind a router
  port-forward) was confirmed healthy — real Steamworks Web API auth
  configured, session signing in explicit mode, durable SQLite storage.
- **Packaged-Electron CORS fix:** a packaged build's renderer origin
  (`file://`, or no `Origin` header at all) would have been silently locked
  out the moment production `HB_ALLOWED_ORIGINS` tightened to real HTTPS
  web origins. Session minting now prefers the preload-context bridge over
  a renderer `fetch()`, and the relay's CORS predicate explicitly allows a
  missing/`file://` origin without weakening the actual session-token
  auth check underneath it.
- **Local dev, unstuck:** a working `npm run server:local` (Node's built-in
  `--env-file`, zero new dependencies) now boots cleanly on its own port,
  side-by-side with the live production container instead of colliding
  with it.

### 🌐 Real Steam Lobby Integration (Friends, Invite, Join Game)

- **SteamLobbyService:** create/join/leave a real Steam lobby, open Steam's
  native Friends invite dialog, and set Steam Rich Presence ("Co-op
  Expedition — 2/4 Operatives", with a working in-client "Join Game")
  directly from the multiplayer panel.
- **Cold-start and live invites both work:** accepting a Friends invite
  while Hunker is closed (`+connect_lobby`) now routes into a single
  running instance via a new single-instance lock, instead of risking a
  second game window; accepting while Hunker is already open is handled
  through Steam's own `GameLobbyJoinRequested` callback.
- **One party identity, not two:** a session that came from a real Steam
  lobby now uses `STEAM-<lobbyId>` as its relay room code, so Steam party
  membership and relay room membership are the same thing instead of two
  states that could drift apart. Room codes remain available for browser
  dev, LAN, and QA.
- Verified against the actually-installed `steamworks.js` runtime, not
  just its type declarations — caught and avoided two API-shape mistakes
  before they shipped (lobby type constants have no runtime object at all;
  the callback-name enum lives on a different export than its own type
  declarations suggest).

### 🛠️ Multiplayer Reliability Hardening

- **World generation is now actually seed-synced.** Co-op/PvP clients were
  independently generating different worlds despite the match seed being
  broadcast identically to everyone — the seed was never wired into world
  generation. Fixed, and verified live with two connected clients producing
  identical world hashes for the same match.
- **Stable cross-client enemy IDs.** Enemy hit resolution moved from fuzzy
  type+position matching toward the same deterministic per-chunk key
  already used for loot-pile depletion, now genuinely reliable since world
  generation is synced. A related respawn bug (a killed enemy's identity
  silently reissued to a new spawn on chunk revisit) was found and fixed
  alongside it.
- **Immediate host failover.** If the co-op/PvP host disconnects mid-match,
  a remaining player is now promoted instantly instead of the room going
  permanently hostless (previously, only a full reconnect or a brand-new
  joiner could restore a host) — closing a real gap left after Sprint 21's
  original host-reassignment fix.
- **Extraction visibility and server-validated co-op damage** round out the
  pass: a squadmate's extraction is now visible to the rest of the room,
  and co-op enemy damage is validated against server-tracked state instead
  of trusted outright from the reporting client.

### ☁️ Steam Stats & Cloud Saves, Actually Wired

- **6 of 8 configured Steamworks stats were dashboard-only.** The counters
  were already tracked in-game the whole time; nothing was reading them
  into the Steam stats sync. All 8 (`total_kills`, `total_runs`,
  `total_victories`, `shells_collected`, `lore_drops_collected`,
  `max_hive_bond`, plus the two already-wired stats) now sync for real.
- **Steam Cloud save sync was dead code.** The Electron-side bridge that
  mirrors save data into the file Steam Cloud actually watches was fully
  built but never called from the game — saves worked fine locally but
  Steam Cloud had nothing to sync. Fixed generically (every current and
  future save key is covered automatically) with a one-time bootstrap sync
  so existing players' progress reaches Steam Cloud on their first launch
  after updating, not only future writes.

### 🎯 Design Direction: "One More Ring"

- A long-form design review of Hunker Bunker's hook, combat feel, and
  narrative direction was distilled into four focused planning docs under
  `docs/design/` — the mechanical/narrative/emotional thesis, a camp
  narrative style guide, a combat-feel/juice checklist, and an AAA-polish
  strategy doc — each grounded in this repo's actual files rather than
  left as abstract brainstorming.
- Two pieces moved from plan to real, tested code: the **Depth Contract**
  (per-ring reward/danger scaling as the first step toward making "one
  more ring" a legible bet) and the first **transformative relic** ("Last
  Breath" — below 20% O2, weapon damage doubles), plus 7 more relics added
  to the catalog and a small narrative-depth pass on three camp leaders'
  death-return dialogue.

## 🛠️ Fixes & Stability

- Fixed the packaged-Electron CORS hazard blocking production Steam auth
  once strict origins are enforced.
- Fixed world generation not actually being seed-synced across
  multiplayer clients despite deterministic generation code already
  existing.
- Fixed a killed-enemy respawn bug (no depletion registry existed for
  ordinary enemies, only for junk piles).
- Fixed immediate host failover on mid-match disconnect (previously only
  reconnect or a new joiner could restore a host).
- Fixed 6 of 8 Steamworks stats never being synced despite being fully
  tracked in-game.
- Fixed the Steam Cloud save bridge being fully built but never called.
- Fixed `window.activeMultiplayerSession`/`isMultiplayer` leaking into a
  solo run started after an earlier multiplayer match in the same tab.
- Fixed a pre-existing typo in two leaders' death-return dialogue lines.

## 📦 Upgrade Notes

- `npm run server:local` is the new default for local backend dev — see
  `.env.loco` (gitignored) and `PRODUCT_STATE.md` for setup notes.
- Production Steam auth and Steam Lobby integration both depend on the
  self-hosted Docker/Caddy deploy documented in `PRODUCT_STATE.md`, not
  the (unused) Fly.io path referenced in older Sprint 26 planning docs.
- Steam Lobby integration is code-complete but not yet live-verified with
  two real Steam accounts — see `docs/steam-lobby-integration-plan-2026-08-20.md`
  for the acceptance test this still needs.
- This remains a beta build. Multiplayer and Steam-integration changes
  should be reported with platform, session mode (co-op/PvP), and
  reproduction steps.
