## Co-op

Reported from a live Steam Deck ↔ PC session, where milestone beats were entirely
local — one player repairing the O₂ generator produced nothing on the other client.

- **Shared world events.** The relay had no channel for world beats at all. Adds
  `worldEvent` → `worldEventBroadcast`, rate limited and payload bounded. The O₂
  milestone now announces itself; peers replay it flagged `fromRemote` so it applies
  exactly once and never echoes back.
- **Shared enemies.** A peer could only *update* enemies it already had locally,
  never create one, so a host-staged boss stayed invisible for the whole fight.
  Snapshots now carry `isBoss`/`scale` and peers materialize a missing boss on
  demand. Ordinary enemies deliberately do not: each client owns its own local
  population, and spawning every snail the host sees would double it.
- **Friendly fire shoves instead of hurting.** A round overlapping a squadmate is
  consumed and pushes them along its travel direction. The impulse is authored by
  the shooter but applied on the target's own client, so position authority is
  never contested. PvP keeps real damage.
- **Solo runs no longer inherit a co-op session.** `clearMultiplayerSession()`
  existed for this but only ran from title NEW RUN and Daily Ops. Two entry points
  leaked — Armory → Deployment Briefing → SOLO, and title CONTINUE — so a solo run
  after any co-op match stayed multiplayer, with stale socket listeners still
  mutating its state.

## Performance — the O₂ build no longer freezes the game

Repairing the O₂ generator blocked the main thread for **21.4 seconds** across two
stalls (`docs/logs/log20.json`, long tasks at 210,817 ms and 221,986 ms). Two
synchronous whole-scene shader recompiles against ~2,139 unique materials:

- `BaseLights.build()` ran from `ignite()`, adding 8 PointLights mid-beat. three.js
  bakes light count into its program cache key, so every lit material needed a new
  program. The grid is now built during world setup, so the light *set* is final
  before gameplay and ignition only ramps intensities.
- A `renderer.compile()` on a 50 ms timer ran *before* the lights were added,
  compiling a program set invalidated moments later — full cost, no benefit. Removed.

The "menu stays open" symptom was the same bug: `closeConsoleModal()` sat behind a
`setTimeout(100)` that could not run for 11 seconds.

## Presentation

- **Post-processing was inert in the shipped build.** The focus predicate gated on
  `cameraMode === 'isometric'`, but the game ships third-person, so `composer.render()`
  never ran for a default-settings player — no tilt-shift, no focus effects, at all.
- **Two blur systems were fighting.** A GPU band blur and a CSS `backdrop-filter`
  radial blur disagreed about where focus was. The shader is now the single blur
  authority; the overlay is vignette-only.
- **Lighting contrast.** Ambient `1.9 → 0.85`, hemisphere `0.8 → 0.55`, directional
  `2.3 → 2.5`, and the directional light now tracks the player with a widened shadow
  frustum — shadows previously vanished past 14 m from spawn.
- **Combat VFX.** Flat ground-plane impact discs replaced with 3D shards that read
  correctly in the third-person camera. Bosses smash destructible walls rather than
  pathing around them.
- **Cutscene timing.** The cutoff rule had been rewritten inline twice and was wrong
  both times — first truncating every clip 0.5 s early, then losing the opening's
  deliberate trim. Now owned and tested in `src/cutsceneTiming.js`: the opening is
  the only trimmed clip, everything else plays to the end.
- Tactical text over video gained a framed backing plate so it survives a bright frame.

## Roguelike legibility

- **The run-card deck was structurally broken.** With WORLD and FACTION capped at one
  each, `patrol_surge` was the only THREAT card — so **every** 3-card draw was forced
  to include it: 206/206 deep draws, 70.5% of all runs. Added three THREAT cards, a
  threat cap, and run-to-run repeat prevention. Now 41% of deep draws, 30% overall,
  with all nine cards landing between 20–34%.
- **Every card promise is a real delta.** Ten effect keys had zero consumers — CAMP
  PARANOIA's *"bond work pays twice as much"* and ICE COLLAPSE's *"one camp needs a
  dig-out route"* were text only. Five were wired to real consumers, five removed with
  their blurbs rewritten. A whole-deck test now fails on any unbacked key.
- **Run cards are visible.** Previously captured and rendered nowhere but a debug-gated
  seed string. Now a HUD chip strip during the run and a line on the death screen.
- **Lore has narrative order.** Drops gained a *lead* (what finding it tells you to do)
  and a *stage*, so setup drains before revelation.
- **Touching a boss hurts.** Contact damage was gated on the AI's chosen target, so a
  boss chewing on the ship could have the player standing inside its body and deal
  nothing. Body contact is now physical, on its own cooldown.

## Session log export and the shared drop box

`~` → EXPORT SESSION produced nothing on PC and an unusable native save dialog on
Steam Deck. Two real bugs: the download anchor was never added to the DOM (a no-op in
Firefox/Electron), and the blob URL was revoked on a 0 ms timer.

Delivery is now chosen by environment — Steam Deck writes straight to disk with no
dialog, `npm run dev` writes into `./logs/` in the repo, and the browser keeps a
fixed blob download. `uploadlogs` plus a server drop box (`POST/GET /logs/session`)
puts Deck and PC captures from one session in one directory, retrievable with
`npm run logs:fetch`.

## Security

- **The upload endpoint was open to the internet** and now fails closed: a missing
  `HB_LOG_UPLOAD_TOKEN` in production returns 503 rather than silently serving a
  public write endpoint.
- **The feature was broken for its actual use case** — a real capture is ~68 MB
  against a 32 MB cap, so uploading exactly the sessions worth reviewing failed.
  Captures are gzipped client-side, and the ceiling applies to the decompressed
  stream so it bounds a decompression bomb as well as an honest upload.
- Resolved CodeQL type-confusion and incomplete-escaping findings; stored content is
  re-serialized by the server rather than relayed from the request.
- Patched 6 dependency advisories including the production `express`/`qs` chain —
  the `qs` denial-of-service reached a host serving the public.

## Engineering

- **Unwired-code audit** (`docs/reports/gameplay-implementation-gap-audit-2026-09-10.md`)
  plus a reusable detector, `scripts/audit-unwired-code.mjs`. This repo has a recurring
  failure mode: a system ships as a pure module with full unit coverage and no call
  site, so it reads as finished everywhere except in the game. Findings include
  anti-softlock route validation that exists and never runs, 8 modules with no
  importer, 74 uncalled exports, and 32 CustomEvents dispatched into nothing.
- **Deployment drift documented.** `~/server/compose.yaml` and the repo's
  `docker-compose.yml` are different files; `~/server` is not a git checkout and its
  build context points at the repo working tree.

## Known gaps

- The O₂ door choreography is designed but not implemented; `orchestrated` is read in
  `threeGame.js` and never set true.
- LAG-03 instrumentation is still open — the stalls reported `activePhases: []`, so
  21 s of blocking was unattributable.
- 9 of 19 relics remain inert, correctly excluded from the reward roll rather than faked.
- A recorded 35–45 minute new-player Proof Run and two-account Steam co-op acceptance
  both remain open.
