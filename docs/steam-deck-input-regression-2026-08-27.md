# Steam Deck Armory and Twin-Stick Input Regression (2026-08-27)

## Symptom

- Armory dropdowns could receive focus but could not be operated reliably with
  Steam Deck controls. After one value change, focus appeared to stop working.
- Right trigger did not behave like A/Confirm in menus.
- The left and right sticks could both stop driving gameplay movement and
  camera/crosshair aim when Steam Input was connected.

## Root cause

This was three related input-boundary defects rather than a gameplay movement
or camera defect:

1. Native Steam Input and Chromium's Gamepad API were selected as complete,
   mutually exclusive controller sources. A stale or partially applied Steam
   layout can still emit a digital action while leaving `move` and/or `camera`
   neutral. That digital action kept `nativeAnyInput` true and suppressed the
   browser fallback. The existing emergency merge rescued only the left stick,
   only during gameplay; it never rescued right-stick aim or menu pointer input.
2. Every Armory equipment change calls `render()` and replaces its controls.
   The focused `<select>` was destroyed and focus was not restored to its
   replacement. Electron also does not reliably open a native select popup from
   the synthetic click generated by controller Confirm. In addition, the option
   builder coerced opaque community chassis IDs (`comm_*`) with `Number(...)`;
   the resulting `NaN` meant the saved choice was never marked selected after
   that re-render, so the dropdown visually snapped back to Standard.
3. The official menu layout bound right trigger to `menu_tab_right`, while the
   browser action router discarded gameplay `fire` when deriving menu actions.
   RT therefore could not act as Confirm on either input path.

## Fix and control contract

- Native buttons remain authoritative, but neutral native `move` and `camera`
  vectors are now filled independently from the browser Gamepad view. This is
  active in gameplay and menus, so one stale analog binding cannot disable the
  other stick.
- Armory re-renders restore focus by control ID. D-pad/stick directions change
  focused selects, disabled/locked choices are skipped, and Confirm advances a
  select deterministically without depending on Chromium's native popup.
  Numeric Steam item IDs and opaque community IDs now retain their correct type
  when option selection is rebuilt.
- A and RT are both Confirm in menus. RT remains Fire in gameplay. The official
  Steam layout revision is now `9.0`, forcing the reworked mapping to replace
  incompatible older official configurations.

| Context | Left stick / D-pad | Right stick | A | RT |
| --- | --- | --- | --- | --- |
| Menus / Armory | Move focus; change focused dropdown | Pointer | Confirm / advance dropdown | Confirm / advance dropdown |
| Gameplay | Move player | Aim / camera / crosshair | Interact | Fire |

## Regression coverage

- `src/browserGamepad.test.js` covers RT menu Confirm and per-stick native/browser
  analog merging, including preservation of a working native stick.
- `src/inputActions.test.js` covers edge-triggered RT Confirm behavior.
- `scripts/build-steam-input-configs.test.js` requires the Deck layout revision
  and native RT-to-`menu_confirm` binding.
- Existing browser gameplay movement and right-stick aim E2E tests remain the
  runtime safety net. A physical Steam Deck pass is still required for hardware
  acceptance; automated tests do not claim that sign-off.
